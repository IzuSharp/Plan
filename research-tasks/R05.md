## 项目与授权边界

NativeWeave 是独立、C# First、严格 Native AOT 兼容的通用原生应用框架。普通应用开发者主要写 C#；只有成熟生态、缺失能力或完整工作负载证据足以支付 FFI 成本时才选择 Rust。纯 C# 应用不得被迫装载 NativeWeave 原生运行时；引擎独立开发、版本管理和发布。ArcForges Design/Plan 只参考文档格式和组织，不能继承其中的内容、规则或验收政策；ArcForges 是下游之一，不得成为依赖。本轮要同时推进阶段 A（完整互操作、生成、构建、验证、引擎接入）和阶段 B（Database、AOT ORM/LINQ、Server、端到端验证）的研究与设计，未来 GUI/GPU/移动端仅证明扩展边界。不直接实施完整产品。不要把探索性 API、候选路径、版本号或实验状态说成已验证事实。

正式研究与设计仓库：https://github.com/IzuSharp/NativeWeave-Design 。计划权威：https://github.com/IzuSharp/Plan 。产品实现仓库：https://github.com/IzuSharp/NativeWeave ，本任务不进行完整产品开发。

## 正常、异常与竞争路径

追踪公共API → 适配 → FFI/运行时 → 状态变化 → 错误处理 → 释放 → 测试。至少覆盖本专题这些风险：

- 生成器漂移；宏后类型不可见；静默不支持；错误生成ABI；缺少稳定诊断

本专题验证重点：**特性/成本矩阵及同一小API的绑定结果对照，不预设采用任一项目**。能执行最小实验时执行；不能执行时给精确命令、前置条件和未执行状态，不编造结果。

每项核心结论记录仓库 URL、不可变 commit SHA（或发布 tag 再解析 SHA）、文件路径、符号、行范围或原文定位、正常/异常/释放路径及对应测试。区分源码证实、实际测试证实、官方文档证实、合理推断、待验证、已否定。候选源码路径仅是定位线索，必须先核实存在；不以 README 替代调用链。覆盖清单列已读/未读/不适用和理由；不能宣称读过整个项目。实验记录工具链、OS/架构、命令、退出码、原始日志与哈希；代码样例状态只能是设计草案、静态审查、编译通过、运行通过、Native AOT 运行通过、独立验证通过之一。禁止用 JIT 成功推导 AOT 成功。许可证需逐一核查，不复制不明许可的代码。无法执行的验证保留阻塞项，不伪造测试结果。
