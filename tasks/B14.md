## Modules and Interfaces

Own explicit native relation/CRUD/CAS policy and narrow C# changeset surface. No implicit lazy loading, identity map, tracking or aggregate save-graph semantics added silently.

C# interfaces:

Relation<TParent,TChild>, EntityKey<TEntity>, Changes<TEntity>, ConcurrencyCheck<TEntity>, LoadRelatedAsync and typed foreign-key changes through UpdateAsync/UpdateCheckedAsync, plus checked CRUD/bulk operations; nullable foreign keys, composite keys, explicit relation loading, NotSet versus NULL and optimistic concurrency remain distinct. Native SQLx/SeaQuery owns execution and grouping.

Rust native reuse:

SeaQuery joins/CRUD and SQLx transactional execution for the ordinary route. SeaORM LoaderTrait offers valuable native batching/grouping but has static ModelTrait/EntityTrait bounds and all() materialization; dynamic eager loading requires an explicit upstream/native adapter scope with bounded grouping, not a C# relation engine.

## Implementation Steps

1. Build joins and projections from explicit relationship metadata; distinguish an unmatched LEFT JOIN row via a nonnullable joined key/null marker rather than a nullable business column alone.
2. Implement NotSet as omitted update column, Null as bound SQL NULL and Value as bound checked value. Construct tenant+key+version predicates in native code before execution.
3. Perform CAS update with version increment, inspect affected rows and return conflict without automatic write replay. Multiple statements use B05 transaction scope.
4. Expose explicit bulk/relationship batches within finite parent/key/result budgets. Initial ordinary baseline supports joins and explicit batches; do not claim SeaORM eager loader is already dynamic or bounded.
5. Any optional dynamic native loader extension must cite the existing SeaORM algorithm/license/pin, prove parent order/duplicate/null/many-to-many semantics and stay separate from basic CRUD acceptance.
6. Public API refinement 0.4.0: Explicit relationship load/link/unlink/CRUD and optimistic concurrency; native execution, no lazy proxies or hidden tracker graph.
7. Public API refinement 0.4.0: Use api_design_inputs and api_design_input_sha256 from the exact pinned Design commit; implement the declared member/type policies and native operation mapping. ## Errors, Cancellation, Memory, and Concurrency

- Tenant scope is never removed by keyset cursor, relation path or recovery query. Composite keys and duplicate parent rows have explicit deterministic handling.
- CAS conflict differs from encoding error, missing row and Unknown commit. Cancellation after write dispatch follows B05, not a fictional rollback guarantee.
- Partial changesets and failed multi-statement updates cannot publish success or leak held parent/cursor/transaction owners.
