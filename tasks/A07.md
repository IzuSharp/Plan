## 可执行实现设计：启动握手、结果与退休

沿用 C-ASYNC-001@0.1.0-draft 的 create/start/request_cancel/take_result/try_retire/release 形状，不新增公共动态 variant，不池化 callback context 或 IValueTaskSource。API 草案仍为 Task<T> + CancellationToken；TCS 使用 RunContinuationsAsynchronously。当前不是产品实施授权。

| 维度 | 状态/屏障 | 不可混淆的含义 |
| --- | --- | --- |
| Native operation | Created → Running → TerminalReady → Retired → Released | terminal 通知冻结结果；try_retire 成功才确认 native 不再触碰 context/输入 |
| Setup | operation 已创建；registration_ready；start_settled 或 never-started 哨兵 | Register 可同步调用取消回调；start 可在返回前同步完成 |
| Managed result | 未发布 → 成功/失败/取消，单次发布 | Task 终态不是 GCHandle、input 或 body 可释放的证明 |
| Cleanup | callback/control-call 计数归零，取消注册排空，result 已 take/drop | managed 屏障与 native Retired 同时满足才 Reclaimed |

实施顺序：先保留 operation slot、owner/input lease 和稳定 managed context；create 成功后登记强 GCHandle cookie，再注册取消并明确 registration_ready。预取消和注册中的同步取消只能请求停止，不抢占 native 终态发布权。start 返回前的完成只排入协调器；等待 start_settled 后才能进入最终释放判定。start 明确拒绝时维持 Created 且无工作/回调留存，直接撤销 setup；接管是否成功不明确时隔离并保留必要 owner，不能推断从未开始。

terminal callback 只复制固定 status/borrowed error、记录通知并交给有界协调器；不持跨语言锁执行用户 continuation。协调器以 take-once 获取 typed result：尚未 take 的 native result 由 operation release 负责；take 成功后立即由托管 owned wrapper 接管，converter 抛错由该 wrapper 恰一次释放。成功发布到 Task 的 OwnedResult 已转移给应用，协调器不能因为无人 await 或重复通知再次释放；应用 Dispose/非阻塞后备释放和独立 held-result 预算承担后续寿命。重复通知锁存为协议缺陷，不触发第二次 take/free。关闭普通业务门后，协调器仍持有内部 take/retire/release 权，不通过已经关闭的业务入口访问 native。

取消注册通过回调外的 DisposeAsync 排空；禁止在 token callback 内同步 Dispose 注册并自等待。native callback、managed cancellation callback、start 和 request_cancel 控制调用分别持有相应 lease；只有 native Retired、setup settled、注册已排空、所有 managed callback/control-call 退出后才能释放 cookie、输入租约与 operation owner。调用者取消 CloseAsync 的等待或达到 deadline 只停止等待，后台 cleanup 仍持有资源并报告 pending retire。

协调器容量在接受操作前预留；每个 operation 通知去重，队列满采用已预留槽位/共享扫描的有界方案，不产生每次失败一个无界 Task、timer 或 waiter。operation slot 在 Reclaimed 或明确转移给独立 owned-result 预算时才归还，不能在 Task 发布时提前复用。

| 竞争/故障测试 | Oracle |
| --- | --- |
| token 预取消、Register 同步回调、注册异常 | start 是否执行有明确记录；所有 setup 分支到达单一清理责任 |
| terminal 在 start 返回之前到达 | 可发布 Task，但 cookie/input 在 start_settled 与其余屏障前不释放 |
| 完成/取消/owner Close 重排 | 唯一 terminal 与唯一 take/drop；关闭后内部退休仍可推进 |
| 未 take 或 take 后 converter 抛错 | 前者由 operation release，后者由托管 wrapper 恰一次释放；不混淆接管边界 |
| OwnedResult 已发布后无人 await、重复/迟到通知 | 已转移结果仍归应用及独立 held-result 预算；不二次 take/free，不重复 TCS 发布或复用旧 cookie |
| callback/control-call 卡住，CloseAsync 超时 | 报告活跃计数和 cleanup age，保留资源并限流；不伪造 quiet |
| 满队列、消费者停止、持续取消 | admitted operations、待回收槽位和持有字节有上界；无丢失最终清理通知 |
