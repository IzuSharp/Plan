## 目标与阶段

C# 是强类型应用层；数据库/ORM 查询关系和 Server 网络协议运行时必须由成熟 Rust 引擎实现。Kestrel/托管驱动只比较。普通 Entity/DTO/Handler 使用维护者预编译 native 模块，正常 dotnet build/run 与 AOT；不重写 C# SQL AST/方言/完整 LINQ，不引入强制巨型 Core runtime。

当前只执行 Research/Documentation 与 Design 研究原型；未来 Delivery 实施仍需明确阶段授权。设计接受不冒充产品、长负载或发布通过。

## 模块与接口

Static diagnostics for known ABI/AOT/ownership hazards; no assertion that analysis proves arbitrary unsafe code safe.

C# 接口：

Actionable NW diagnostic IDs with source spans, severity, explanation and local fix where sound.

Rust 原生复用：

Roslyn incremental analyzer/semantic model, framework AOT diagnostics; no runtime analysis service.

## 实施步骤

1. Implement D03 diagnostic set: unsupported wire types, invalid callback signatures, escaped borrow/ref-like values, missing required schema and conflicting export IDs.
2. Detect forbidden generator side effects/build hooks and unsupported dynamic reflection paths in owned surface where statically knowable.
3. Use compilation cancellation correctly and avoid retaining Compilation/Symbol graphs globally.
4. Document false-positive limits and narrow reviewed suppressions; unsupported uncertainty must not emit unsafe code.

## 错误、取消、内存与并发

- Analyzer cancellation discards unpublished results and retains no user compilation objects.
- Do not label absence of diagnostics as ownership/concurrency proof.

## 验收要求

- Positive/negative source tests with exact diagnostic spans, incremental edits and cancellation; no tests that merely mirror implementation branches.
- Real Native AOT compile verifies analyzer guidance does not hide framework warnings.

- Windows x64; Linux x64
- ordinary dotnet build/run; for generators/analyzers this describes the produced consumer, not the compiler host; explicit-RID Native AOT publish and actual consumer execution on the required OS rows
- Independent NuGet where this component is distributed; full no-Rust pristine consumer gates A16/B24.
- Exact source/lock/features/native/package/executable hashes; component tests cannot claim assembled product success.
- The task-specific cases below plus D04–D09; native and managed retirement separately observed.

依赖理由：start pins only actually consumed completed modules; acceptance adds local assembled-runtime checks where required. Reference links alone never become a global barrier.
