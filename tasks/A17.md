## Implementation steps

1. Wrap real pinned native algorithm in minimal C exports and explicit owner release; opt out of executor/callback capabilities.
2. Use fallible checked admission and bounded decompressor; state honest OOM/unwind limits and partial-output drop behavior.
3. Consume through generated facade and independent NuGet ordinary/AOT application.
4. Record incremental Engine code/dependency/package costs and compare direct Rust behavior without numerical superiority claims.
5. Keep codec raw-input, compressed-input and decompressed-output limits separate. A successful compression must be admissible by this same profile decoder: reserve a source-justified worst output/peak bound or fail compression before owner publication when the encoded result would exceed its input cap. Never copy the finite fixture same-4MiB-input assumption into a product round-trip guarantee.

## Errors, cancellation, memory and concurrency

- Malformed or oversized/decompression-bomb inputs expose no partial owner; empty input handled explicitly.
- Synchronous algorithm does not advertise cancellation after the noninterruptible native call starts.

## Acceptance requirements

- Direct Rust versus C# versus ZLibStream round-trip for varied sizes, malformed input and limit; creating allocator frees exactly once.
- Windows/Linux AOT and no global Tokio startup; independent app change preserves native hash.
- Inject a deterministic managed-wrapper construction exception after native success returns a non-null owned result but before managed ownership commits; assert exactly-once release of the raw native owner, no partial result, leak or double free.
