## 目标与阶段

C# 是强类型应用层；数据库/ORM 查询关系和 Server 网络协议运行时必须由成熟 Rust 引擎实现。Kestrel/托管驱动只比较。普通 Entity/DTO/Handler 使用维护者预编译 native 模块，正常 dotnet build/run 与 AOT；不重写 C# SQL AST/方言/完整 LINQ，不引入强制巨型 Core runtime。

当前只执行 Research/Documentation 与 Design 研究原型；未来 Delivery 实施仍需明确阶段授权。设计接受不冒充产品、长负载或发布通过。

## 模块与接口

Maintainer Rust C-export scaffolding and symbol inventory, not application-specific Rust codegen.

C# 接口：

No public application API; outputs used by native Engine maintainer build.

Rust 原生复用：

csbindgen/cbindgen or source-informed static wrappers per D03 evidence; reuse repr(C)/native owner APIs.

## 实施步骤

1. Generate or verify exports from the same A09 inventory with unsafe extern/no_mangle rules and exact error/output postconditions.
2. Wrap actual Engine public APIs; explicitly map unsupported types instead of exporting Rust layout.
3. Compare produced C header/import/export lists and linker symbols; fail missing or unexpected ABI exports.
4. Record generator/tool/adapter/upstream identities and make no Cargo invocation from C# entity changes.

## 错误、取消、内存与并发

- A generator warning with omitted export is a hard inventory failure.
- catch_unwind does not justify continuing a poisoned Engine or freeing memory through a different allocator.

## 验收要求

- C/Rust/C# signatures/layout parity, changed-source drift rejection and negative unsupported tuple/generic cases.
- Build and execute exports on Windows MSVC and Linux GNU with final linked symbol inventories.

- ['Windows x64', 'Linux x64']
- ['ordinary dotnet build/run; for generators/analyzers this describes the produced consumer, not the compiler host', 'explicit-RID Native AOT publish and actual consumer execution on the required OS rows']
- Independent NuGet where this component is distributed; full no-Rust pristine consumer gates A16/B24.
- Exact source/lock/features/native/package/executable hashes; component tests cannot claim assembled product success.
- The task-specific cases below plus D04–D09; native and managed retirement separately observed.

依赖理由：start pins only actually consumed completed modules; acceptance adds local assembled-runtime checks where required. Reference links alone never become a global barrier.
