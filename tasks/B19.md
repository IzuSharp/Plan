## 项目边界

NativeWeave独立于ArcForges，ArcForges只参考格式。C#是应用开发层，正式消费必须Native AOT。Database底层必须Rust，managed驱动只作源码/基准对照；Rust Server可选且需证据。优先源码驱动深度复用；普通新实体使用预编译native能力，不默认Cargo/CI。自然typed Fluent优先，不要求完整IQueryable/EF，不在C#重写SQL AST/方言。SG可选生成static metadata/DTO，不是唯一查询路径。Core只提供可组合ABI/lifetime/buffer/error/async，无巨型runtime。保留严格安全和生产验收，不授权大规模产品实现。

## 精确 host 选择门禁

B15 Kestrel 与 B17 Rust 均是 undecided 产品候选；Kestrel 比较研究不自动选择 B15。selection_inputs 中每个 profile 必须明确 selected/excluded，server-host 组至少一个 selected；可以两个都 selected，不产生隐含默认。两者都 excluded 或仍有 undecided 时，本任务既不能 ready，也不能终结接受。

条件依赖：

- B15@0.2.1：start；host与该协议在host上的profile均selected时才需要实际host；现有D19仅提供Kestrel接缝，Rust需额外accepted设计。
- B17@0.2.2：start；host与该协议在host上的profile均selected时才需要实际host；现有D19仅提供Kestrel接缝，Rust需额外accepted设计。

selected start 边同时约束开始和接受；selected acceptance 边约束最终接受。两种 host 同时选中须分别提供真实实现/平台证据。选择状态、任务 revision 与内容 digest 进入验收快照；组合变化使旧审查失效。该机制仅修正未来候选任务依赖，不授予产品实施权限。

## 协议与 host profile 能力前置

当前 D19 / C-PROTOCOL-001@0.1.0-draft 的 managed ASP.NET/gRPC/MCP SDK 接缝是 Kestrel-specific 的候选设计，尚未接受，不能据此声称可直接运行于 Rust host。protocol_host_profiles 独立列出协议在哪个 selected host 启用：B15 条目引用当前精确协议设计，B17 暂无适用 adapter 契约（contract_input=null），两条目均 undecided。

本任务若 selected，至少一个全局 selected host 上的协议 profile 也要 selected；每个全局 selected host 的协议启用/排除必须明确。启用条目须绑定本任务 contract_inputs 中精确 accepted 协议设计。Rust-only + 协议 selected 时，无相应 Rust host 能力/adapter 设计不能 ready 或终结接受；未来须先修订 D19 的 host-specific API/ownership/transport 能力、接受新精确契约，再修订本任务版本与矩阵。不能隐含安装 Kestrel、把 Unsupported 当成 selected 特性已实现，或复制未审查 SDK middleware 来绕过前置。

双 host selected 可以明确只在 Kestrel profile 启用协议，Rust profile 标 excluded，并在发布 capability 矩阵如实说明；若两边均启用，两边各需对应 accepted 设计和真实 adapter/Native AOT/transport 证据。不能把任意 ASP.NET middleware 当可互换的 Rust Service。协议包整体 excluded 时不得出现在已完成发布能力中；调低选择要显式修订版本/组合并让旧审查失效。

未来验收针对每个启用 profile 记录具体 SDK/adapter 版本、静态 serializer/route、协议握手、正常流与取消、超时、client disconnect、shutdown、输入限额、认证/TLS 边界和 Windows/Linux 真实 AOT 消费。负例包括 Rust-only 且缺设计、选中未实现能力、host 已排除而协议 profile 被启用，以及同时选择两host却复用一份 transport 报告。结构 ready 不能代替这些能力和语义审查；实施授权绑定当前任务及矩阵的完整内容 hash。

profile对应的accepted协议spec还必须含唯一的 json nativeweave-protocol-host-profiles-v1 fenced JSON声明（host_task_ids数组）。声明属于既有spec字节及content_sha256/独立Review的接受对象；当前Kestrel接缝只可声明B15，但本轮spec尚无该机器声明，故仍有未接受/缺声明前置。不能把B17改映射到同一个Kestrel-only契约绕过；无声明也阻断。增加B17会改变spec hash并使旧契约证据/Review失效，必须重新按原有机制接受。
