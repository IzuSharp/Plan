## 目标与阶段

当前只执行 Research/Documentation 与 Design 研究原型；未来 Delivery 实施仍需明确阶段授权。设计接受不冒充产品、长负载或发布通过。

## 模块与接口

Immutable coordinated package release with independently identified native Engine assets.

C# 接口：

NuGet managed facade/native RID assets and optional maintainer crate; no user Rust build hooks.

Rust 原生复用：

NuGet archive/restore rules plus native dependency inventory, optional SBOM/signing tools outside product.

## 实施步骤

1. Package exact validated artifacts and license/NOTICE/source manifest; bind external package digest without circular self-hashing.
2. Run pristine no-Rust independent consumer: restore/build/run, offline-after-restore edit and explicit-RID AOT publish/execute.
3. Add an Entity/DTO/Handler and verify native hash unchanged; missing feature produces clear diagnostic instead of rebuilding Rust.
4. Verify provenance identity/subject digest and compatibility matrix before immutable publication; retain rollback package set.
5. Build D10 exact owned-package closure: normalized package ID/version entries, explicit dependency edges using exact [V] NuGet ranges, Engine/RID/ABI/capability and native payload hashes. Unrelated ecosystem dependencies retain their separately reviewed policy.
6. Provide build-transitive validation after restore and before build/publish that compares resolved owned packages and selected native metadata to the accepted closure, emitting a hard mismatch error even if application direct overrides or suppressed NU1608/NU1605 warnings would otherwise restore. A13 integrates shared targets; A02 supplies independent runtime bootstrap compatibility checks.
7. Verify the complete closure from isolated staging on the declared Windows/Linux profiles, upload immutable dependency leaves before facades, journal each package outcome, then read back and restore every required destination package before exposing the catalog. Partial publication has no atomic rollback.
8. On 409 or retry/skip-duplicate, read the existing package and verify allowed signing identities, accepted payload entries/nuspec/dependencies/native hashes before resumption. Record upload and downloaded archive hashes separately; legitimate repository-signature envelope change is checked by a package-signature verifier, never by ignoring arbitrary differing entries. A payload or identity conflict stops this release and requires a new version.
9. Unlist/deprecate is visibility guidance: known-version restores and caches remain. Preserve a previously tested complete closure for deployment rollback; do not hot-unload or replace a native module in an existing process.

## 错误、取消、内存与并发

- Hash integrity is not publisher authentication; unknown builder or unexpected digest fails release.
- Atomic promotion covers local staging/release manifest only. NuGet/crate uploads have no cross-package transaction: publish immutable leaves first, verify the entire set before publishing its release catalog, and resume or withdraw catalog exposure after partial failure without overwriting released bytes.

## 验收要求

- Both OS clean-image consumption and runtime-only execution; restored asset manifest matches actual loaded native hash.
- License/transitive closure, tampered/missing/native ABI negatives and old/new coordinated package combinations.
- Inspect owned-package nuspec exact [V] edges and test application direct-version override with NU1608 warnings both enabled and suppressed; the project closure hard-error still rejects the invalid package/native profile.
- Exercise missing leaf/RID, partially published closure, matching existing ID/version, conflicting existing payload, allowed repository-signature-envelope renewal versus changed payload/nuspec/native entry, and unlisted known-version restore. A successful subset of uploads or skip-duplicate response never accepts a complete release.
- Restore and execute the complete accepted closure from an independent source/cache on clean Windows/Linux no-Rust consumers; capture uploaded/downloaded archive identities, signature verification, native-file hashes, full per-package journal and previous-complete-closure rollback.

- Windows x64; Linux x64
- ordinary dotnet build/run; for generators/analyzers this describes the produced consumer, not the compiler host; explicit-RID Native AOT publish and actual consumer execution on the required OS rows
- Independent NuGet where this component is distributed; full no-Rust pristine consumer gates A16/B24.
- Exact source/lock/features/native/package/executable hashes; component tests cannot claim assembled product success.
- The task-specific cases below plus D04–D09; native and managed retirement separately observed.

依赖理由：start pins only actually consumed completed modules; acceptance adds local assembled-runtime checks where required. Reference links alone never become a global barrier.
