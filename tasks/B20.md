## 项目边界

NativeWeave独立于ArcForges，ArcForges只参考格式。C#是应用开发层，正式消费必须Native AOT。Database底层必须Rust，managed驱动只作源码/基准对照；Rust Server可选且需证据。优先源码驱动深度复用；普通新实体使用预编译native能力，不默认Cargo/CI。自然typed Fluent优先，不要求完整IQueryable/EF，不在C#重写SQL AST/方言。SG可选生成static metadata/DTO，不是唯一查询路径。Core只提供可组合ABI/lifetime/buffer/error/async，无巨型runtime。保留严格安全和生产验收，不授权大规模产品实现。

## 可执行实现设计：关闭协调与可核对诊断

接入所有 selected host，B15/B17 至少选择一者并锁定 selection snapshot；没有全局默认 host。公开的 ShutdownCoordinator、Activity/Meter 接缝为草案，具体实现服从 C-SERVER-001@0.2.1-draft、B16 的所有权与选定 host 的真实行为。

关闭按可观测阶段推进：拒绝新业务准入 → 请求已有工作停止 → 关闭队列准入并 drain 既有 reservation/message → 等待 handler/head、body 和 retained frame → native/managed callback 与取消注册排空 → 最后释放 owner。每阶段记录启动时间、已完成数和仍阻塞的 owner 类型。具体依赖图允许并行 drain，不把顺序示意误作一把全局锁；任何释放都必须满足其自己的屏障。

CloseAsync 的 caller cancellation/deadline 与后台清理分离；超时输出未回收对象/字节/permit/worker 数和 cleanup age，限制新准入或隔离 Engine。不能把 Tokio runtime shutdown_timeout、SQLx Shutdown ack、Task terminal 或日志里“closed”当全部 OS worker 已 join 的依据。底层同步阻塞调用须移出 callback/finalizer，并有可追踪容量与停止进展策略。

观测至少区分 admitted/rejected requests、active heads/bodies、queued items、outstanding reservations、retained allocation bytes、native/managed callback、pending retire、transaction Unknown 与 poisoned connections。每个 counter 定义增减线性化点，所有出口都能对账；标签为低基数，不写 SQL 参数、body、token 或用户秘密。跨 FFI 只传必要关联 metadata，不自动重复创建 trace/provider；关闭观测时不留下强 root 或 background loop。

测试从 head 已结束但 body/Bytes/permit 仍活跃的状态开始 Close；注入迟到取消、handler 卡住、consumer 消失、并发重复 Close 与 deadline。验证新请求被拒绝、未清理工作仍可诊断、资源不会因超时提前归零，最终合作退出时计数收敛。观测开/关和不同采样率使用相同负载量化 CPU/分配/RSS/p99；用敏感字段负例检查日志。不以 metrics 数值为零单独证明未计量的 native 内存或 OS 线程已退休。

观测与准入账本包含 Closing/retirement-pending 的全部活动 owner；不得把它们从 A 计数移出后仍持续接受等量新请求。EndObserved 与已知 transport completion/reset 原因分别记录，未知原因不补造成功标签。
