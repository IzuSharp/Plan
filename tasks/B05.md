## 可执行实现设计：commit Unknown 与连接退休

输入为 C-TX-001@0.2.1-draft 与 C-DB-001@0.2.0-draft。SQLx 是候选驱动能力，不强制所有 provider 先实现 SeaORM ConnectionTrait/TransactionTrait；若选 SeaORM profile，另记录 trait、错误和 session 接缝。普通实体和查询继续使用预编译 native 资产。产品实现前仍需 accepted 契约、正式阶段授权与精确依赖。

| 独立状态 | 至少区分的值/事实 | 责任 |
| --- | --- | --- |
| 事务生命周期 | Active、CommitDispatched、Finalizing、Closed | 固定物理 session lease；不把连接释放当业务结果 |
| 持久化结果 | Committed、RolledBack、Unknown，以及尚无结果 | 只有可证实的确认可决定效果；未知 commit 不自动重试 |
| 连接协议/处置 | 同步可复用、需要 drain、poison/retire | 由 backend 确认是否允许返池，不从 Task 终态推导 |
| 本地生命周期 | 有活动 worker/lease/回调、停止准入、完成本地退休 | 与远端效果解耦；Unknown 可写入独立恢复记录后安全释放本地内存 |

COMMIT 的 dispatch 是必须记录的边界。之后取消、超时或连接断开，若缺少提交确认，结果保持 Unknown；后续 Drop 发出的 rollback、连接关闭成功、TaskCanceledException 都不能把它改写为 RolledBack。恢复 API 提供 operation/transaction correlation 和应用幂等键，以新查询核实业务状态；不在通用层重复未知写入。只有从未 dispatch COMMIT 的 rollback 确认，或能可信绑定到原事务终态的恢复证据，才可确立 RolledBack。进入 Unknown 后，后续 cleanup rollback 成功或“无活动事务”响应只更新协议清理/连接处置，不能改写原持久化效果；细化 Unknown 必须有身份绑定的恢复证据，也不能覆盖已经证实的 commit。

SQLx Transaction Drop/start_rollback 可能只把命令排入 worker；返回不证明数据库已经回滚或物理连接可交给下个租户。provider 必须在既有 worker 串行模型内完成 drain/探测、确定 conn disposition，再归还 pool permit。SQLite 的临时表/物理连接标记用于证明“同一连接”复用，不能仅因后续查询成功就认为复用了原连接。取消源应按操作代际隔离并拆除旧 progress/interrupt handler；旧 cancel 迟到不能影响新租户。

区分 worker 已释放 connection 引用、Shutdown ack、OS thread closure 返回和 JoinHandle 已完成；没有公开 JoinHandle 时不能声称已 join。SQLx 的同步 bounded-channel send 可能阻塞调用线程，Tokio timeout 不能抢占这段同步 send。适配设计须说明该调用在哪个执行上下文、容量如何预留、何时拒绝新工作，以及停止进展后的隔离/诊断，不在 finalizer 或 callback 中阻塞等待。

| 必须执行的验收 | 判定与证据边界 |
| --- | --- |
| COMMIT 已发送而响应方向 ACK 丢失（真实 PostgreSQL 故障注入） | 数据库侧效果可查；客户端 Unknown；无盲目重试；恢复记录与服务端事务对应 |
| SQLite commit hook 暂停，丢弃已 dispatch 的 Future，再放行 | 允许实际已提交；不得误报 rollback；后续普通 rollback 仍正常 |
| Drop 活动事务 + 单连接池复用 | 未提交行消失、同一物理 session 标记保留；不能只检验新连接查询成功 |
| row 流提前停止、单连接 pending acquire 取消 | row/stream owner 回收，permit 不丢失，连接按 drain 规则可复用 |
| 旧取消迟到、rollback/drain 失败、pool.close 与借出 owner 并发 | 新操作不被旧 flag 取消；坏连接隔离；close 拒绝新 acquire 并等待既有 owner |
| callback/控制调用尚在途，业务结果已发布 | 不提前释放 native session/context；安全退休后才归还本地资源 |

已存在的 Design 输入是 docs/database/sqlx-retirement-study.md 和 experiments/database-retirement/：六项 SQLite 原生实验覆盖 worker/Drop、commit Future 丢弃、流早停、pool acquire、progress handler 和 close；Design run 43375871731 在 Windows/Linux 均执行六项，具体输入与日志以 paired checkpoint 的 verification/source-lifecycle/results.json 为准。它未执行 PG 丢 ACK、C# Native AOT/CLR 取消注册退休、任意 sqlite3_step 中断、弱内存、soak、全进程 RSS 或生产 adapter；这些保留为本任务与 B22 的未来门禁，不能重复标为完成。
