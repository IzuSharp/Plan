## Implementation Steps

1. Implement exactly the D15 four independent dimensions: TxLifecycle Active/Failed/CommitInFlight/RollbackInFlight/Closed; TransactionOutcome InProgress/Committed/RolledBack/Unknown; ConnectionDisposition Usable/ProviderResetPending/Quarantined/Discarded; LocalLifetime Live/Closing/Quiescent/Reclaimed. Private internal states require an explicit mapping and may not weaken these public observations.
2. The CommitAsync admission token can reject before the conservative provider-commit dispatch boundary. After entering CommitInFlight, use a separate finite commit deadline; request cancellation or loss of a trustworthy reply cannot replace Unknown with Cancelled or RolledBack. Reject Commit while Failed and distinguish trustworthy COMMIT confirmation from failed-transaction termination.
3. Run rollback/drain/probe through cleanup admission on the original session. Known ordered provider maintenance may be ProviderResetPending; unknown protocol damage is Quarantined and cannot be loaned to another tenant. Return the permit only when reuse is safe or physical retirement has completed; close_on_drop is intent, not observed retirement.
4. For unconfirmed rollback without any COMMIT attempt, expose Closed/InProgress, CommitAttempted=false, Cleanup=RollbackUnconfirmed and quarantine. After a previous Unknown COMMIT, every later cleanup rollback or no-transaction response leaves Unknown unchanged. Preserve primary and cleanup errors separately.
5. Implement explicit savepoint stack/generation and isolation capabilities on the same session. SQLite Deferred/Immediate is not a PostgreSQL isolation matrix; unsupported levels fail before begin. Ordinary commands cannot change transaction ownership through raw transaction-control SQL.
6. CloseAsync closes public admission, requests or joins already-admitted transaction/cursor cleanup and may return Pending with LocalResourcesReleased=false. The Engine retains parents, callbacks, roots and budgets until safe retirement. DisposeAsync joins the same cleanup and cannot claim success while access remains possible; synchronous Dispose only transfers cleanup responsibility without blocking a finalizer.
7. Propagate recovery ID and D20 tenant/key/request-hash identity without creating an automatic business retry service. PG ReadCommitted conflict recovery uses a subsequent SELECT statement; one missing same-statement CTE result or cleanup completion never proves rollback. Persist uncertainty separately from releasable native owners.
8. Public API refinement 0.4.0: DataTransaction/savepoint/commit-result/cleanup APIs preserve unknown remote outcome, poisoned session handling and bounded close.
9. Public API refinement 0.4.0: Use api_design_inputs and api_design_input_sha256 from the exact pinned Design commit; implement the declared member/type policies and native operation mapping. Update task-owned XML, generated API Reference contribution, guide and minimal/advanced consumer source together. For internal-only scopes document applicability and expose no accidental public plumbing.

## Errors, Cancellation, Memory, and Concurrency

- Drop may queue rollback but does not confirm it. Commit dispatch, application result, transaction effect, protocol reuse and local retirement remain independently observable.
- A stale cancellation generation cannot affect the next session owner. Cleanup after public close remains admitted; failed or unknown protocol cleanup cannot return a connection to the next tenant.
- Unknown may outlive released native resources as a managed or durable recovery identity. A bounded HTTP flow uses CloseAsync explicitly and must not immediately follow Pending with an implicit indefinite await-using DisposeAsync join.
- Automatic cleanup never overwrites the primary business or CommitUnknown error. Explicit rollback errors remain visible in their own result and Cleanup snapshot.
