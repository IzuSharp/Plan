## Implementation Steps

1. Implement Mutable→Sealed→Submitted/Closed/Poisoned with single-writer admission. Immutable sealed shape and each execution parameter snapshot are distinct owners.
2. Translate typed metadata/operations directly into SeaQuery public APIs; retain metadata owner and aliases. Value placeholders remain values, identifiers come from trusted metadata.
3. Validate backend capabilities before SeaQuery render and before send: reject SQLite row lock/SELECT INTO/SEARCH CYCLE, unsupported CTE/ANY/SOME/ALL or named-window cardinality instead of accepting upstream ignore/panic.
4. Implement ordinary CRUD, joins, aggregates, bounded subqueries/CTE/window capabilities with SQL three-valued logic; call B07 once for native binding and propagate its error.
5. Cache immutable compiled shapes only under finite entries/bytes and exact ABI/profile/metadata/query keys. Eviction retains in-use owners; no cache of mutable argument buffers.

## Errors, Cancellation, Memory, and Concurrency

- Cross-query expression/alias transfer requires explicit native clone or rejection, never pointer reuse; Dispose races are admission failures.
- Seal failure is either no mutation/retryable or explicit Poisoned; caught panic cannot leave a valid-looking partially changed builder.
- No client-side hidden expression evaluation or C# NULL compensation.
