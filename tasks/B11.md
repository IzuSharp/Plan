## 目标与阶段

当前只执行 Research/Documentation 与 Design 研究原型；未来 Delivery 实施仍需明确阶段授权。设计接受不冒充产品、长负载或发布通过。

## 模块与接口

Own actual SeaQuery AST/builder/capability checking and managed narrow binding adapter; call B07 for Arguments conversion. B09 owns operation declaration, B13 application Fluent composition.

C# 接口：

Internal native query/plan owner and typed operation calls; public high-level Fluent surface is B13.

Rust 原生复用：

SeaQuery Expr/Condition/Select/Insert/Update/Delete/Dialect and SQLx B07 binder. No C# SQL parser/emitter, no duplicated Rust SQL builder.

## 实施步骤

1. Implement Mutable→Sealed→Submitted/Closed/Poisoned with single-writer admission. Immutable sealed shape and each execution parameter snapshot are distinct owners.
2. Translate typed metadata/operations directly into SeaQuery public APIs; retain metadata owner and aliases. Value placeholders remain values, identifiers come from trusted metadata.
3. Validate backend capabilities before SeaQuery render and before send: reject SQLite row lock/SELECT INTO/SEARCH CYCLE, unsupported CTE/ANY/SOME/ALL or named-window cardinality instead of accepting upstream ignore/panic.
4. Implement ordinary CRUD, joins, aggregates, bounded subqueries/CTE/window capabilities with SQL three-valued logic; call B07 once for native binding and propagate its error.
5. Cache immutable compiled shapes only under finite entries/bytes and exact ABI/profile/metadata/query keys. Eviction retains in-use owners; no cache of mutable argument buffers.

## 错误、取消、内存与并发

- Cross-query expression/alias transfer requires explicit native clone or rejection, never pointer reuse; Dispose races are admission failures.
- Seal failure is either no mutation/retryable or explicit Poisoned; caught panic cannot leave a valid-looking partially changed builder.
- No client-side hidden expression evaluation or C# NULL compensation.

## 验收要求

- For every supported operation compare direct Rust SeaQuery SQL, placeholder order, typed arguments and real PG/SQLite result/errors against C#→ABI.
- Property/negative tests: malformed raw operations, SQL injection through value vs identifier, nonfinite/overflow values, NULL joins, Unicode, empty sets, capability mismatches and budget exhaustion.
- Same-native-hash ordinary entity changes and Windows/Linux AOT, with fallible binder source owned by B07 only.

- ['Windows x64', 'Linux x64']
- ['ordinary dotnet build/run; for generators/analyzers this describes the produced consumer, not the compiler host', 'explicit-RID Native AOT publish and actual consumer execution on the required OS rows']
- Independent NuGet where this component is distributed; full no-Rust pristine consumer gates A16/B24.
- Exact source/lock/features/native/package/executable hashes; component tests cannot claim assembled product success.
- The task-specific cases below plus D04–D09; native and managed retirement separately observed.
