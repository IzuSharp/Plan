## 可执行实现设计：native builder、backend 拒绝与 fallible binder

Rust 的 SeaQuery AST/SQL 方言是查询结构权威，SQLx 执行参数化语句；C# 仅发 typed descriptor/操作和参数，不重建第二套 SQL AST、方言或 IQueryable provider。依 C-QUERY-001@0.2.1-draft，先直接组合公开 API，只有固定源码证实缺口时才提出小范围 upstream extension。

| 对象/阶段 | 不变量 | 失败后的责任 |
| --- | --- | --- |
| Query owner | 元数据 profile、backend、owner identity 固定；每次可变调用单 writer 准入 | SafeHandle 只保活，不能产生多个并发 Rust &mut |
| Mutable → Sealed → Submitted → Closed | Sealed 后禁止修改；提交采用参数快照；释放拒绝新入口 | 一次 seal/submit 的失败须说明可重试或转 Poisoned |
| Expr/Column proxy | entity/alias/type 与 query owner 相符 | 跨 query 默认拒绝，只有显式 native clone 才可转移 |
| Bind/encode | checked narrowing、明确 null/type/backend codec；值只走参数 | 每个转换 fallible；失败不发送半条 SQL、不泄漏已分配的参数 owner |
| Compiled shape/cache | 查询形状和每次执行值独立；cache 有界且拥有 metadata | metadata 失效和 eviction 不留下悬空 proxy/参数 |

将能力检查放在可能 panic、静默降级或发送前：SQLite row lock、SELECT INTO、SEARCH/CYCLE 等不支持项按固定版本能力表拒绝；ANY/SOME/ALL、空 CTE/非法结构不得走到 upstream assert/panic。检查所有支持 backend 的边界，不能仅在 C# builder 检查后信任未经验证的 FFI 输入。Rust panic 只在 ABI 边界受控转换，不作为正常 Unsupported 的实现。

SQL NULL 遵从 SQL 三值逻辑；显式 IsNull/IsNotNull，不自动模拟 C# nullable 比较补偿。标识符来自可信 typed metadata/allowlist，不作为任意字符串拼接；排序、分页、join alias、group/having、CTE/window 等各有正例和拒绝例。当前检查到的单 named-window 槽位不是任意多 window 支持；若要扩展，单列源码差异、公开接缝、许可证与差分测试，不能在 packet 中假设能力已存在。

批量 builder 命令须有版本、长度、节点数、递归深度与总字节上限；先验证再提交，或定义可证明的 rollback/Poisoned 行为，不能让半次 AST 修改继续执行。这是 builder 的局部原子性，不等于数据库事务回滚。

验收逐 query 比对直接 Rust SeaQuery 与 C#→ABI 的 SQL、占位符顺序、参数类型/值及真实 PostgreSQL/SQLite 结果；包含 SQL3VL、checked overflow、非有限浮点 profile、Unicode/标识符、空集合、跨 owner、Dispose/写入竞态、混合 backend、非法 ABI payload 和预算耗尽。执行“受支持普通新 entity/字段变化后 native hash 完全相同”及无 Rust/Cargo 的干净消费者 AOT 测试。固定 SQLx/SeaQuery 源码与锁文件、差分 oracle 和失败 seed；未支持的语义明确拒绝，不以只生成 SQL 冒充真实 backend 执行。
