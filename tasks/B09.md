Task revision **0.3.0**. Graph: `delivery-graph.json`; the graph is authoritative for current status, exact source commits and acceptance records. This document is one of the existing 114 standalone task packets.

## Objective and phase

C# is the strongly typed application layer; Database/ORM queries and relations and the Server networking/protocol runtime must be implemented by mature Rust engines. Kestrel/managed drivers are comparators only. Ordinary Entity/DTO/Handler types use native modules precompiled by maintainers, with normal dotnet build/run and AOT; do not reimplement a C# SQL AST/dialects/full LINQ or introduce a mandatory monolithic Core runtime.

Only Research/Documentation and Design research prototypes are executed in the current phase; future Delivery implementation still requires explicit phase authorization. Design acceptance does not claim product, sustained-load or release validation has passed.

## Modules and interfaces

Own minimal query-operation ABI descriptors and query owner IDs under Query.Binding/native/database/binding. Import canonical metadata/value/result shapes from B01; do not publish another Table/Column schema or a serialized C# SQL AST.

C# interfaces:

Internal typed call descriptors and owner/alias tokens used by B10/B11/B13, with public application types from B01.

Rust native reuse:

Versioned calls target SeaQuery-native builder operations. Start with direct native operations; batching is an optional measured encoding optimization with identical semantics, not a prerequisite or second query language.

## Implementation steps

1. Define direct operation contracts for query create, predicates/joins/projection/order/limit, seal and execute plan reference, plus capability errors and legal state transitions.
2. Distinguish synchronous borrowed parameter input from copied/owned async arguments. A business descriptor hash is content identity, not Engine ABI fingerprint.
3. Bind owner identity and alias/type metadata to each operation. Raw ABI validation repeats type/capability/size checks; C# generics are not the only protection.
4. If implementing batches later, retain finite version/node/depth/bytes and prevalidate all operations before applying; failure cannot leave an executable partly mutated AST.

## Errors, cancellation, memory and concurrency

- Reject unknown opcode/capability/version, wrong owner, reused/disposed owner and overflow before mutation.
- Use Core D08 statuses and bounded structured domain detail; do not export a new generic runtime object/trait abstraction.
