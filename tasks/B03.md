## 模块与接口

Own SQLite native provider, connection options, worker-specific hooks and adapter test fixtures; use the B04 host and shared transaction/stream/codec components.

C# 接口：

Sqlite options for file path, WAL/FK, busy timeout and supported transaction begin mode; common strongly typed Session/query facade.

Rust 原生复用：

SQLx SQLite worker, SQLite prepared statements, progress hooks and transaction machinery. No unconditional Task.Run wrapper and no separate C# database execution engine.

## 实施步骤

1. Pin libsqlite3-sys/SQLite build features and actual SQLite version in the native package. Configure FK/WAL/busy profile explicitly on every physical connection; validate in-memory pooling semantics.
2. Implement one active operation per physical connection and bounded native command admission. Account separately for queued item count, input bytes and driver allocations.
3. Use an operation-generation-scoped progress cancellation flag installed/removed on the worker. An old cancel request cannot affect a new tenant. Do not promise interruption at every native instruction.
4. Separate Future drop, queued rollback, worker connection destruction, shutdown ACK and OS-thread join evidence. Close awaits only facts the API can actually observe; do not label an unavailable JoinHandle as joined.

## 错误、取消、内存与并发

- Synchronous bounded-channel send can block its caller; a Tokio timeout cannot preempt that code. Reserve capacity or use a controlled worker path and avoid blocking finalizer/reverse-callback threads.
- busy/locked/progress-interrupt errors preserve provider detail and require transaction cleanup; per-connection FK/savepoint behavior is tested.
- Huge cells may already be allocated inside SQLite/SQLx before boundary rejection; report observed allocation separately from the owned-batch budget.

## 验收要求

- Reuse existing database-retirement six-case two-OS research as oracle definitions, then execute actual product paths for commit Future drop, rollback/pool reuse, progress cancellation, early stream drop and shutdown.
- Windows/Linux AOT use file-backed concurrent connections plus documented in-memory cases; foreign-key failure/savepoint recovery and native migration checksum/failing-DDL tests.
- Same-connection reuse uses a persistent physical-connection marker; a fresh connection succeeding is not the oracle.

- ['Windows x64', 'Linux x64']
- ['ordinary dotnet build/run; for generators/analyzers this describes the produced consumer, not the compiler host', 'explicit-RID Native AOT publish and actual consumer execution on the required OS rows']
- Independent NuGet where this component is distributed; full no-Rust pristine consumer gates A16/B24.
- Exact source/lock/features/native/package/executable hashes; component tests cannot claim assembled product success.
- The task-specific cases below plus D04–D09; native and managed retirement separately observed.
