## Implementation Steps

1. Implement one runtime method router and four public native service adapters; copy/release payload ownership through Core operations.
2. Use generated C# protobuf models/typed parsers; no runtime schema compiler or reflection-discovered services.
3. Keep Tonic framing/compression/trailers/statuses native; preserve framed length OutOfRange11 versus decompression ResourceExhausted8.
4. Implement strict small Rust deadline policy: one1–8-digit timeout+H/M/S/m/u/n, checked/capped monotonic budget starting at admission; invalid3/expired4 statuses.
5. Keep deadline and body/operation owner alive after response head; private Tonic GrpcTimeout is not callable and only wraps ResponseFuture.
6. Integrate all method kinds and conformance clients under Windows/Linux Native AOT.
7. Construct a fresh Decoder for each request and selected method kind. Unary/server-stream methods accept exactly one frame, including a zero-byte protobuf message; reject a second frame with InvalidArgument(3) before Handler invocation. Client/bidi streaming permits multiple frames within total quota.
8. Public API refinement 0.4.0: Optional static C# gRPC mapping exposes four cardinalities through Tonic on B17; status/trailers/deadline/flow-control semantics.
9. Public API refinement 0.4.0: Use api_design_inputs and api_design_input_sha256 from the exact pinned Design commit; implement the declared member/type policies and native operation mapping. Update task-owned XML, generated API Reference contribution, guide and minimal/advanced consumer source together. For internal-only scopes document applicability and expose no accidental public plumbing.

- C# serialization temporary memory and native retained message buffers are independently charged.
