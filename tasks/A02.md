## Objective and Phase

C# is the strongly typed application layer; database/ORM queries and relationships and Server networking/protocol runtimes must be implemented by mature Rust engines. Kestrel/managed drivers are comparison baselines only. Ordinary Entity/DTO/Handler code uses maintainer-precompiled native modules with normal dotnet build/run and AOT; do not reimplement a C# SQL AST/dialects/full LINQ or introduce a mandatory monolithic Core runtime.

The current scope is Research/Documentation and Design research prototypes only; future Delivery implementation still requires explicit phase authorization. Design acceptance must not be presented as successful product, long-running-load, or release acceptance.

## Modules and Interfaces

Engine-local loading, bootstrap and capabilities; no global service locator or universal function table.

C# interfaces:

AbiVersion, EngineCapability, EngineInfo, EngineDescriptor.Inspect, EngineLoadOptions and EngineCatalog provide immutable bootstrap/capability metadata; Engine instances remain independently owned.

Rust native reuse:

OS native loader and D02 C ABI; optional function table only for an Engine that needs one.

## Implementation Steps

1. Resolve packaged native assets through SDK-supported application-local loading; verify identity/RID/ABI and required capabilities.
2. Read only supported bootstrap prefixes; reject incompatible major and missing required bits without partial owners.
3. Support engine-prefixed fixed imports first; opt-in table validates every required pointer and retains module lifetime.
4. Keep module loaded for process lifetime and instances separately disposable; emit bounded Engine/version/RID diagnostics.
5. Public API refinement 0.4.0: AbiVersion, EngineCapability, EngineInfo, EngineDescriptor, EngineLoadOptions and EngineCatalog metadata/capability/preflight behavior.
6. Public API refinement 0.4.0: Use api_design_inputs and api_design_input_sha256 from the exact pinned Design commit; implement the declared member/type policies and native operation mapping. Update task-owned XML, generated API Reference contribution, guide and minimal/advanced consumer source together. For internal-only scopes document applicability and expose no accidental public plumbing.
