## Objective and phase

C# is the strongly typed application layer; Database/ORM queries and relations and the Server networking/protocol runtime must be implemented by mature Rust engines. Kestrel/managed drivers are comparators only. Ordinary Entity/DTO/Handler types use native modules precompiled by maintainers, with normal dotnet build/run and AOT; do not reimplement a C# SQL AST/dialects/full LINQ or introduce a mandatory monolithic Core runtime.

Only Research/Documentation and Design research prototypes are executed in the current phase; future Delivery implementation still requires explicit phase authorization. Design acceptance does not claim product, sustained-load or release validation has passed.

## Modules and interfaces

Rust native reuse:

OS native loader and D02 C ABI; optional function table only for an Engine that needs one.

## Implementation steps

1. Resolve packaged native assets through SDK-supported application-local loading; verify identity/RID/ABI and required capabilities.
2. Read only supported bootstrap prefixes; reject incompatible major and missing required bits without partial owners.
3. Support engine-prefixed fixed imports first; opt-in table validates every required pointer and retains module lifetime.
4. Keep module loaded for process lifetime and instances separately disposable; emit bounded Engine/version/RID diagnostics.

## Errors, cancellation, memory and concurrency

- Missing assets or unsupported feature never select a managed driver/host fallback.
- No unload while any call/callback/release can execute; unknown optional fields remain ignored/defaulted.
