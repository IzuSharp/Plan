## 目标与阶段

C# 是强类型应用层；数据库/ORM 查询关系和 Server 网络协议运行时必须由成熟 Rust 引擎实现。Kestrel/托管驱动只比较。普通 Entity/DTO/Handler 使用维护者预编译 native 模块，正常 dotnet build/run 与 AOT；不重写 C# SQL AST/方言/完整 LINQ，不引入强制巨型 Core runtime。

当前只执行 Research/Documentation 与 Design 研究原型；未来 Delivery 实施仍需明确阶段授权。设计接受不冒充产品、长负载或发布通过。

## 模块与接口

Optional affinity/device/platform probes, isolated from mandatory desktop Core.

C# 接口：

Typed dispatcher/capability/lifecycle interfaces for explicitly supported profile only.

Rust 原生复用：

R32/R33 mature UI/GPU/event-loop/device APIs; native Engine preserves thread-affine ownership.

## 实施步骤

1. Implement minimal affinity capability descriptor and owner-thread dispatch without adding a global GUI/GPU runtime.
2. Exercise main-thread access, queue close, device/window loss and deferred resource release/fence ordering in supported probe.
3. Define explicit unsupported-target behavior for mobile/static-link/WASM profiles and required toolchain/licensing prerequisites.
4. Document extension conformance changes and incremental Core impact; future platform code stays outside current mandatory release.

## 错误、取消、内存与并发

- Send/Sync cannot be inferred from a pointer; caller wrong-thread use rejected before source-affine operation.
- Timeout/device loss does not imply GPU completion or safe immediate native deallocation.

## 验收要求

- Affinity access/retire race and unsupported capability negatives on actual available targets; no simulated success for unavailable device.
- Windows/Linux cross-language capability/lease tests; device-specific certification stays explicit separate target evidence.

- ['Windows x64', 'Linux x64']
- ['ordinary dotnet build/run; for generators/analyzers this describes the produced consumer, not the compiler host', 'explicit-RID Native AOT publish and actual consumer execution on the required OS rows']
- Independent NuGet where this component is distributed; full no-Rust pristine consumer gates A16/B24.
- Exact source/lock/features/native/package/executable hashes; component tests cannot claim assembled product success.
- The task-specific cases below plus D04–D09; native and managed retirement separately observed.

依赖理由：start pins only actually consumed completed modules; acceptance adds local assembled-runtime checks where required. Reference links alone never become a global barrier.
