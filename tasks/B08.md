## Modules and Interfaces

Own explicit deployment migration runner and ledger policy; never automatic destructive schema synchronization in ordinary DataSource startup. Keep administration pools/sessions separate from request transactions.

C# interfaces:

Explicit MigrationDefinition/Manifest and ApplyAsync administrative entrypoint with provider, ID, hash, from/to compatibility and transaction mode.

Rust native reuse:

SQLx Migrator/Migrate, native migration checksums, provider transactional DDL and ledger. Provider-specific locking is inspected, not assumed identical.

## Implementation Steps

1. Build the migration manifest from trusted application/admin artifacts, not untrusted table-name strings. Stable same-ID/same-hash succeeds idempotently; changed hash rejects.
2. For PostgreSQL, execute on a dedicated admin connection. Migrator error paths can return before session advisory unlock; close the connection on every exit path, and prove lock disappearance.
3. For SQLite, SQLx lock/unlock is a no-op. Reject no_tx entries before admission, use Connection::begin_with("BEGIN IMMEDIATE") to obtain a depth-tracked Transaction, and Migrator::run(&mut *tx). Explicitly commit success or rollback error, retaining cleanup failure and closing a damaged connection. Never raw query BEGIN: it bypasses SQLx depth and causes nested-BEGIN error. Serialize checksum/DDL/ledger under the writer lock.
4. Initial supported profile is transactional migrations. Statements incompatible with that transaction are explicitly rejected or require a separately specified recovery-phase profile; never label partially executed DDL atomic.
5. Persist exact migration/hash/provider/phase and define crash/resume behavior without treating a connection-close success as unknown business commit resolution.

## Errors, Cancellation, Memory, and Concurrency

- Do not return an errored migration connection to a shared pool with an advisory lock held.
- SQLite WAL does not serialize concurrent migrators by itself; test busy timeout and acquiring the writer lock before history reads.
- Cancellation must complete native cleanup and release or close the administrative connection; no implicit schema repair on startup.
