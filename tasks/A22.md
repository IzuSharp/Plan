## 目标与阶段

C# 是强类型应用层；数据库/ORM 查询关系和 Server 网络协议运行时必须由成熟 Rust 引擎实现。Kestrel/托管驱动只比较。普通 Entity/DTO/Handler 使用维护者预编译 native 模块，正常 dotnet build/run 与 AOT；不重写 C# SQL AST/方言/完整 LINQ，不引入强制巨型 Core runtime。

当前只执行 Research/Documentation 与 Design 研究原型；未来 Delivery 实施仍需明确阶段授权。设计接受不冒充产品、长负载或发布通过。

## 模块与接口

Upstream/package/ABI/behavior compatibility and patch upgrade verification.

C# 接口：

Maintainer compatibility manifest and version-matrix runner; no runtime auto-update service.

Rust 原生复用：

Actual upstream API/source maps, Cargo.lock/checksums and package/provenance tooling.

## 实施步骤

1. Compare old/new public/private seams, layout/capability/schema/semantic versions, selected features/MSRV and dependency/license changes.
2. Run old managed/new native and new managed/old native compatibility plus incompatible major/feature negatives.
3. Bind fork patch queue to exact upstream and differential tests with exit owner; prefer public replacement when available.
4. Record security cooldown exceptions and rollback immutable package set; baseline performance method from D13.

## 错误、取消、内存与并发

- A source tag or package version alone cannot prove compiled artifact identity.
- Same ABI bytes with changed SQL/error/cancel semantics still requires compatibility decision.

## 验收要求

- Deliberately incompatible layout/capability/semantic changes fail, compatible optional minor passes on both OS.
- Manifest/provenance substitution, stale artifact and changed private seam negatives; reviewed update/rollback record.
- Verify compatible/incompatible exact package-closure evolution, permitted author/repository signature identity and payload/nuspec/native verification, same-version conflict handling, unlist behavior and rollback to the previous complete closure. Never disable signature or identity checks to make a retry succeed.

- Windows x64; Linux x64
- ordinary dotnet build/run; for generators/analyzers this describes the produced consumer, not the compiler host; explicit-RID Native AOT publish and actual consumer execution on the required OS rows
- Independent NuGet where this component is distributed; full no-Rust pristine consumer gates A16/B24.
- Exact source/lock/features/native/package/executable hashes; component tests cannot claim assembled product success.
- The task-specific cases below plus D04–D09; native and managed retirement separately observed.

依赖理由：start pins only actually consumed completed modules; acceptance adds local assembled-runtime checks where required. Reference links alone never become a global barrier.
