## 项目边界

NativeWeave独立于ArcForges，ArcForges只参考格式。C#是应用开发层，正式消费必须Native AOT。Database底层必须Rust，managed驱动只作源码/基准对照；Rust Server可选且需证据。优先源码驱动深度复用；普通新实体使用预编译native能力，不默认Cargo/CI。自然typed Fluent优先，不要求完整IQueryable/EF，不在C#重写SQL AST/方言。SG可选生成static metadata/DTO，不是唯一查询路径。Core只提供可组合ABI/lifetime/buffer/error/async，无巨型runtime。保留严格安全和生产验收，不授权大规模产品实现。

## 可执行实现设计：自然 typed Fluent 与动态 metadata

以 B09 descriptor 和 B11 native owner/AST 为唯一结构源。候选 C# 接缝为 Query<TEntity>、Column<TEntity,TValue>、受作用域约束的 expression/alias proxy、明确 owned result/stream；这里是未编译 API 形状，正式签名以接受的 C-QUERYGEN-001@0.2.0-draft 与 C-QUERY-001@0.2.1-draft 为准。

1. 普通应用以手写 static metadata 或可选 SG 生成的等价 metadata 注册 entity/table/column、type codec 与静态 DTO materializer；两条路径能力一致，不要求 per-entity Rust、运行时 Reflection.Emit 或 expression compilation。
2. Fluent 操作立即送入 Rust builder，或进入有明确版本和预算的批次；C# proxy 只携带 owner/typed descriptor，不保存第二套查询树或 SQL 方言。
3. 每个值在约定的调用/提交点快照；await 后不再次读取可变 closure。join 要显式 alias，列必须匹配 entity/type/query owner；动态 field 入口经过 metadata allowlist 并在 native 再校验。
4. Seal/Submit/Dispose 与单 writer admission 遵从 B11；复用 query shape 时独立传入新参数，不共享可变 argument buffer。DTO 构造由 B12 承担，物化抛错仍释放 row/batch/result owner。

设计示例和编译 fixtures 至少覆盖 filter + order + limit、typed join/alias、projection DTO、显式关系/批量、参数化查询缓存及受控动态列。SQL 三值语义、缺失映射、不支持表达式和 backend-specific 能力通过静态诊断或明确运行时错误说明；不退回客户端隐藏求值，不加入隐式 lazy loading/identity map/tracking。

负例包括错 entity 列、错 TValue、跨 query proxy、已 Dispose 的 builder、Seal 后修改、并发修改、闭包值在提交前后变化、参数溢出、任意动态标识符、DTO 转换失败及流提前 break。可静态拒绝的例子要有真实编译失败 oracle，其余要验证 native 未发送不安全 SQL且资源计数归零。完整 IQueryProvider/EF 兼容不是本任务验收条件。

在同一预编译 native 二进制下新增两个受支持的普通 entity/DTO，分别走手写 metadata 与 SG；Windows/Linux PublishAot 后真实查询与流处理成功，native SHA-256 不变、消费环境未调用 Cargo/Rust、无反射 fallback。Rust schema-specific 扩展只允许明确选定的特殊 profile，不能作为普通新增 entity 的隐含成本。对比直接 Rust、C# 原生绑定和必要 managed 基准的完整负载成本，不预先声称零分配或更快。
