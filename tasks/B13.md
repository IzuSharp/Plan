## 目标与阶段

C# 是强类型应用层；数据库/ORM 查询关系和 Server 网络协议运行时必须由成熟 Rust 引擎实现。Kestrel/托管驱动只比较。普通 Entity/DTO/Handler 使用维护者预编译 native 模块，正常 dotnet build/run 与 AOT；不重写 C# SQL AST/方言/完整 LINQ，不引入强制巨型 Core runtime。

当前只执行 Research/Documentation 与 Design 研究原型；未来 Delivery 实施仍需明确阶段授权。设计接受不冒充产品、长负载或发布通过。

## 模块与接口

Own natural application-facing typed Fluent calls/proxies under Query.Fluent; no persistent managed SQL tree. B11 owns builder, B09 operation descriptors, B12 DTO materialization.

C# 接口：

Query<TEntity>, typed columns, scoped aliases/expressions, typed Select<TDto>, async execute/stream; handwritten and SG metadata are equivalent paths.

Rust 原生复用：

Direct SeaQuery builder calls and shared runtime metadata; optional batching only if supported by B09 with measured benefit.

## 实施步骤

1. Map every Fluent operation to the native owner immediately; retain only typed owner/descriptor/proxy references required by the user interface.
2. Snapshot each value at its documented call or submit point, before await; do not reread mutable closures. Reused query shapes take new isolated parameter owners.
3. Enforce query/alias/entity/value type association, explicit IS NULL/IS NOT NULL and deterministic page tie-breakers; dynamic external fields resolve metadata allowlist and native validation.
4. Connect seal/execute/cursor and DTO projection without assuming generator availability. Unsupported constructs fail with structured capability diagnostics, never fall back to a hidden managed LINQ engine.

## 错误、取消、内存与并发

- Concurrent mutations, mutation after Seal, cross-query proxy, wrong backend, parent closing and repeated dispose are explicit errors with preserved resource safety.
- Enumeration mapping failure or cancellation releases current batch then completes cursor/session cleanup through B06/B04.

## 验收要求

- Compile negatives for wrong TEntity/TValue/alias use; runtime wrong-owner and disposed query negatives; closure value mutation before/after snapshot oracle.
- Real filter/order/limit, explicit join, aggregate, CTE/window capability and projection examples in clean Windows/Linux NuGet consumers; same native hash for new supported entities.
- Record direct-operation call/copy costs for B23; no zero-overhead or full EF compatibility acceptance claim.

- ['Windows x64', 'Linux x64']
- ['ordinary dotnet build/run; for generators/analyzers this describes the produced consumer, not the compiler host', 'explicit-RID Native AOT publish and actual consumer execution on the required OS rows']
- Independent NuGet where this component is distributed; full no-Rust pristine consumer gates A16/B24.
- Exact source/lock/features/native/package/executable hashes; component tests cannot claim assembled product success.
- The task-specific cases below plus D04–D09; native and managed retirement separately observed.

依赖理由：Preserve local implementation prerequisites; run composition acceptance with actual providers without blocking unrelated implementation work.
