## Objective and phase

C# is the strongly typed application layer; Database/ORM queries and relations and the Server networking/protocol runtime must be implemented by mature Rust engines. Kestrel/managed drivers are comparators only. Ordinary Entity/DTO/Handler types use native modules precompiled by maintainers, with normal dotnet build/run and AOT; do not reimplement a C# SQL AST/dialects/full LINQ or introduce a mandatory monolithic Core runtime.

Only Research/Documentation and Design research prototypes are executed in the current phase; future Delivery implementation still requires explicit phase authorization. Design acceptance does not claim product, sustained-load or release validation has passed.

## Implementation steps

1. Use A21 controller with B21 applications and B22 correctness oracles; keep DB durability/TLS/serialization/query semantics equal.
2. Measure cold/warm, small/large payload, low/high concurrency, streaming and overload with raw histograms and repeated processes.
3. Attribute FFI/DTO/copy/managed/native allocation and runtime threads, plus RSS/working set/package/build/application edit costs.
4. Report adverse/unsupported cells and confidence intervals; propose optimisations only with source/lifetime tradeoff and repeatable benefit.

## Errors, cancellation, memory and concurrency

- Invalid functional oracle, unequal workload or generator saturation invalidates benchmark.
- Do not declare Rust faster from a microbenchmark, language name or single favourable percentile.
