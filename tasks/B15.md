## 目标与阶段

C# 是强类型应用层；数据库/ORM 查询关系和 Server 网络协议运行时必须由成熟 Rust 引擎实现。Kestrel/托管驱动只比较。普通 Entity/DTO/Handler 使用维护者预编译 native 模块，正常 dotnet build/run 与 AOT；不重写 C# SQL AST/方言/完整 LINQ，不引入强制巨型 Core runtime。

当前只执行 Research/Documentation 与 Design 研究原型；未来 Delivery 实施仍需明确阶段授权。设计接受不冒充产品、长负载或发布通过。

## 模块与接口

C# application/Handler/DI/static serializer surface; B17 owns actual native host.

C# 接口：

- NativeServerBuilder, NativeServer, typed route descriptors, WeaveRequest/Response, generated JsonTypeInfo registrations.
- Application-to-native registration contains Handler IDs and immutable metadata; no per-route Cargo or Rust code generation.
- One reusable registered native dispatch callback enqueues bounded managed work; business delegates never run synchronously under native locks.

Rust 原生复用：

- Required Rust Server B17 provides all transport/protocol/runtime resources.
- C# .NET static JSON metadata and existing Core binding generator provide the application surface.

## 实施步骤

1. Implement immutable validated builder/route/serializer configuration with duplicate/unsupported feature diagnostics.
2. Use the accepted Server operation table and Core loader to bind the native module; write no managed HTTP parser/listener.
3. Create one application/DI request scope after successful admission; invoke typed Handler on managed scheduler and complete native operation exactly once.
4. Provide owned async body APIs by consuming B16; release DTO/input/result owners on mapping failure and cancellation.
5. Implement ordinary local consumption and Native AOT package tests after B17 is available.
6. Native callback delivers only a request/operation ticket. Managed scheduled work performs typed take_request outside the callback, then creates the application request scope; do not transfer request owners through the callback itself.

## 错误、取消、内存与并发

- Reject unknown serializer/route/capability before serving.
- Handler exception maps to bounded HTTP error only before headers commit; after commit close/reset with diagnostic.
- Task completion does not release body backing bytes or GC roots before native retirement.

## 验收要求

- Normal dotnet build/run from an independent NuGet consumer without Rust installed; publish and execute win-x64 and linux-x64 Native AOT.
- No product implementation is authorized now; this is refinement of the existing 48 Delivery tasks.
- Use existing Core ABI/create-start/take-result/retire contracts; do not create another callback protocol or mandatory global runtime.
- No private upstream APIs exposed as stable ABI; pin Cargo/NuGet/features and reject incompatible native assets before callback registration.
- Two applications add different Handler/DTO types while loading byte-identical precompiled Rust binary.
- Real HTTP1/HTTP2 native-host request on Windows/Linux AOT; exception, cancellation, disposed app and duplicate route negative cases.

- Windows x64; Linux x64
- ordinary dotnet build/run; for generators/analyzers this describes the produced consumer, not the compiler host; explicit-RID Native AOT publish and actual consumer execution on the required OS rows
- Independent NuGet where this component is distributed; full no-Rust pristine consumer gates A16/B24.
- Exact source/lock/features/native/package/executable hashes; component tests cannot claim assembled product success.
- The task-specific cases below plus D04–D09; native and managed retirement separately observed.

依赖理由：start pins only actually consumed completed modules; acceptance adds local assembled-runtime checks where required. Reference links alone never become a global barrier.
