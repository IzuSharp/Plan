## Objective and Phase

C# is the strongly typed application layer; database/ORM queries and relationships and Server networking/protocol runtimes must be implemented by mature Rust engines. Kestrel/managed drivers are comparison baselines only. Ordinary Entity/DTO/Handler code uses maintainer-precompiled native modules with normal dotnet build/run and AOT; do not reimplement a C# SQL AST/dialects/full LINQ or introduce a mandatory monolithic Core runtime.

The current scope is Research/Documentation and Design research prototypes only; future Delivery implementation still requires explicit phase authorization. Design acceptance must not be presented as successful product, long-running-load, or release acceptance.

## Modules and Interfaces

C# application/Handler/DI/static serializer surface; B17 owns actual native host.

C# interfaces:

- NativeServer.CreateBuilder, NativeServerBuilder, NativeServerApplication, ServerRoutes/RouteGroupBuilder/ServerEndpointBuilder, RequestContext, ServerRequest/ServerResponse, ServerResult/Results and typed handler/filter/middleware/auth interfaces.
- Source-generated endpoint registration and static JsonTypeInfo metadata avoid arbitrary Delegate binding, runtime expression compilation and per-handler Cargo builds.
- One rooted native dispatch/control bridge schedules bounded managed work; business delegates do not execute synchronously under native locks.

Rust native reuse:

- Required Rust Server B17 provides all transport/protocol/runtime resources.
- C# .NET static JSON metadata and existing Core binding generator provide the application surface.

## Implementation Steps

1. Implement immutable validated builder/route/serializer configuration with duplicate/unsupported feature diagnostics.
2. Use the accepted Server operation table and Core loader to bind the native module; write no managed HTTP parser/listener.
3. Create one application/DI request scope after successful admission; invoke typed Handler on managed scheduler and complete native operation exactly once.
4. Provide owned async body APIs by consuming B16; release DTO/input/result owners on mapping failure and cancellation.
5. Implement ordinary local consumption and Native AOT package tests after B17 is available.
6. Native callback delivers only a request/operation ticket. Managed scheduled work performs typed take_request outside the callback, then creates the application request scope; do not transfer request owners through the callback itself.
7. Public API refinement 0.4.0: NativeServer/NativeServerBuilder/NativeServerApplication routing, RequestContext, typed handlers/results, middleware/filters/auth and static JSON.
8. Public API refinement 0.4.0: Use api_design_inputs and api_design_input_sha256 from the exact pinned Design commit; implement the declared member/type policies and native operation mapping. Update task-owned XML, generated API Reference contribution, guide and minimal/advanced consumer source together. For internal-only scopes document applicability and expose no accidental public plumbing.

## Errors, Cancellation, Memory, and Concurrency

- Reject unknown serializer/route/capability before serving.
- Handler exception maps to bounded HTTP error only before headers commit; after commit close/reset with diagnostic.
- Task completion does not release body backing bytes or GC roots before native retirement.
