## Objective and Phase

C# is the strongly typed application layer; database/ORM query relationships and Server networking/protocol runtimes must be implemented by mature Rust engines. Kestrel/managed drivers are comparison baselines only. Ordinary Entity/DTO/Handler code uses maintainer-precompiled native modules with normal dotnet build/run and AOT; do not reimplement a C# SQL AST/dialects/full LINQ or introduce a mandatory monolithic Core runtime.

The current scope is Research/Documentation and Design research prototypes only; future Delivery implementation still requires explicit phase authorization. Design acceptance must not be presented as successful product, long-running-load, or release acceptance.

## Modules and Interfaces

Only production host: Rust Tokio/Hyper/Tower/Axum composition, Engine-local runtime and native network/protocol/connection/shutdown.

C# interfaces:

- Size/version/capability Server table uses server_create/start, request_dispatch/read, response_begin/write/finish, request_abort, server_close.
- Runtime descriptor registry maps C# Handler IDs/routes to one compiled native ForeignService.
- Engine-local ClosePending retains module/runtime/callback/operation owners; actual thread join is a separate obligation.

Rust native reuse:

- Tokio1.54.1, Hyper1.12.0/hyper-util0.1.21, Tower0.5.3; selective Axum0.8.9 routing; rustls0.23.46.
- One engine-owned native runtime; no Kestrel fallback, duplicate TLS or per-handler Rust compilation.

## Implementation Steps

1. Build native module and schema table under this task ownership; regenerate bindings through A10/A11.
2. Configure bounded listeners/connections/H2 streams/handshakes, routes and native TLS before admitting requests.
3. Wrap Service response with B16 body/byte/request ownership extending past Tower response-future permit release.
4. Dispatch managed callback via bounded engine queue, complete waiting native Future on C# response, and preserve exact terminal/retirement competition.
5. Implement admission stop, drain/abort, monotonic deadlines and quiescence without forced module unload.
6. Verify public trait seam compatibility and package native assets; request upstream extension/fork only for a concrete unexposed capability.
7. Reuse A02 negotiated Engine loader/bootstrap and lifetime; do not implement a second module loader or capability protocol.
8. Native callback delivers only a request/operation ticket. Managed scheduled work performs typed take_request outside the callback, then creates the application request scope; do not transfer request owners through the callback itself.

## Errors, Cancellation, Memory, and Concurrency

- Panic/handler exception, late response, rejected dispatch, body reset, failed certificate/config or occupied port unwind owned resources.
- Do not interpret Hyper Body None as peer consumption or always-normal transport end.
- TLS config reload validates a whole immutable new snapshot; old handshakes retain old config; private keys never enter traces.

## Acceptance Requirements

- Normal dotnet build/run from an independent NuGet consumer without Rust installed; publish and execute win-x64 and linux-x64 Native AOT.
- No product implementation is authorized now; this is refinement of the existing 48 Delivery tasks.
- Use existing Core ABI/create-start/take-result/retire contracts; do not create another callback protocol or mandatory global runtime.
- No private upstream APIs exposed as stable ABI; pin Cargo/NuGet/features and reject incompatible native assets before callback registration.
