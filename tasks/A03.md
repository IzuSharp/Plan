## 可执行实现设计：物理租约与业务准入

本节细化未来产品任务；当前只允许在 Design 做研究。精确输入为 D04 的 C-LIFETIME-001@0.1.0-draft、D02 ABI 和本任务已接受的依赖；不得因研究探针通过而跳过契约接受。v1 使用 private opaque pointer、每种资源的 SafeHandle、独立准入门，代际表只用于另有证据的特殊 profile。

| 内部职责 | 候选实现与所有权 | 可观测判定 |
| --- | --- | --- |
| EngineHandle | 唯一 native release 权；ReleaseHandle 不执行用户代码、不等待异步工作；创建器和释放器严格配对 | 每个成功创建的 owner 最终 release 恰一次 |
| AdmissionGate | Open → Closing → Released；同一短临界区内检查 Open 并取得 SafeHandle 引用 | 关闭线性化点之后的普通调用在进入 FFI 前失败 |
| CallLease | 内部不可重复释放的调用作用域；finally 配平 AddRef/Release，锁外执行 FFI | 已获准调用可在 Close 后完成，最后 lease 退出前内存存活 |
| Parent/child ownership | child 只选择一种权威父 lease；native Arc 或明确托管 lease，禁止两边循环持有 | 父停止新业务后，合法 child 按领域契约继续或显式级联取消 |
| Close capability | 预先持有的内部 stop/release 能力，不再进入已关闭的业务门 | stop 抛错也归还 owner，不阻塞 finalizer |

具体控制流为：创建失败保持 out=null 并回滚已取 owner；调用在门内检查逻辑状态、AddRef、读取私有地址，门外调用，finally 释放；Dispose 在同一门内只把 Open 变 Closing，门外请求停止并释放 wrapper owner。不能先检查 closing 再无同步 AddRef；不能把 DangerousGetHandle 或 GC.KeepAlive 当租约；不能从一次 AddRef 成功推导业务仍可进入。SafeHandle 可能因旧 lease 保持物理存活，这正是单独准入门需要拒绝新调用的情形。

本任务实现 Interop.Lifetime 与其测试，不复制 A04 buffer、A06 callback 或 A07 retirement 协议。异步操作通过明确 owner/输入/module lease 交给 A07；同步 CallLease 不可跨 await。私有 lease 不以可随意复制的 public struct 暴露。线程亲和资源将最后释放交给所属线程/执行器；该路径未建立前不得声称支持 GUI/GPU profile。

| 验收场景 | 必须观察的结果 |
| --- | --- |
| 持有旧 lease，Dispose，再尝试新调用 | 旧调用完成；新调用零次 native 进入；最后 lease 退出才发生一次 free |
| 检查准入/AddRef/Dispose 三者交错 | 使用可控 barrier 固定关闭前后顺序；无 TOCTOU、重复 release 或悬空访问 |
| 创建、父 lease 获取、错误转换中故障 | out=null 或单一 owner；所有已取 lease 配平；失败计数与回收计数可对账 |
| 父先关、child 正在调用、双 Dispose、GC/finalizer 压力 | 明确 child policy；无父 state 提前 free，无 finalizer 等待用户回调 |
| 同时操作两个独立 Engine | 无全局句柄表/锁串行所有引擎；错误释放函数负例在隔离进程执行 |

将 Design 中“物理保活不等于逻辑准入”的探针作为反例输入。正式证据仍需 Windows/Linux 的真实 C# Native AOT + Rust ABI、原始日志和制品 hash；有限 Rust 探针不证明 CLR、弱内存、线程亲和或长期资源稳定。记录 free/active leases/rejected admissions 三组计数及竞态 seed，失败保留可复放日志。
