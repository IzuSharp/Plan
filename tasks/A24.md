## 目标与阶段

C# 是强类型应用层；数据库/ORM 查询关系和 Server 网络协议运行时必须由成熟 Rust 引擎实现。Kestrel/托管驱动只比较。普通 Entity/DTO/Handler 使用维护者预编译 native 模块，正常 dotnet build/run 与 AOT；不重写 C# SQL AST/方言/完整 LINQ，不引入强制巨型 Core runtime。

当前只执行 Research/Documentation 与 Design 研究原型；未来 Delivery 实施仍需明确阶段授权。设计接受不冒充产品、长负载或发布通过。

## 实施步骤

1. Generate only opted-in ABI/ownership/error/buffer/async/affinity pieces from a minimal Engine descriptor.
2. Include exact upstream/crate/patch/features/target provenance and source/test coverage obligations.
3. Run scaffold through A17 synchronous and A18 async profiles and show unchanged Core modules where no new common capability is needed.
4. Keep product application variation as metadata/managed methods; scaffolding is a maintainer action, never hidden consumer compilation.

## 错误、取消、内存与并发

- Unknown required capability/layout or missing owner release fails scaffold validation.
- Do not export private source layout or automatically create a global executor.

## 验收要求

- Two heterogeneous real Engine scaffolds compile and pass respective conformance; generated imports/export inventory matches.
- Independent package consumption and deliberate unsupported schema/feature negative; exact template source/hash.

- ['Windows x64', 'Linux x64']
- ['ordinary dotnet build/run; for generators/analyzers this describes the produced consumer, not the compiler host', 'explicit-RID Native AOT publish and actual consumer execution on the required OS rows']
- Independent NuGet where this component is distributed; full no-Rust pristine consumer gates A16/B24.
- Exact source/lock/features/native/package/executable hashes; component tests cannot claim assembled product success.
- The task-specific cases below plus D04–D09; native and managed retirement separately observed.

依赖理由：start pins only actually consumed completed modules; acceptance adds local assembled-runtime checks where required. Reference links alone never become a global barrier.
