## 目标与阶段

C# 是强类型应用层；数据库/ORM 查询关系和 Server 网络协议运行时必须由成熟 Rust 引擎实现。Kestrel/托管驱动只比较。普通 Entity/DTO/Handler 使用维护者预编译 native 模块，正常 dotnet build/run 与 AOT；不重写 C# SQL AST/方言/完整 LINQ，不引入强制巨型 Core runtime。

当前只执行 Research/Documentation 与 Design 研究原型；未来 Delivery 实施仍需明确阶段授权。设计接受不冒充产品、长负载或发布通过。

## 模块与接口

Explicit maintainer-only MSBuild/Cargo orchestration and shared root build manifests.

C# 接口：

Normal consumer build sees prebuilt package assets; maintainer build command accepts target/features/source pins.

Rust 原生复用：

Cargo JSON compiler-artifact and SDK asset rules; reproducible explicit commands.

## 实施步骤

1. Own root solution/Cargo workspace/build manifests through integration lock; task branches submit narrow registration patches, not concurrent parent-directory ownership.
2. Separate host generators from target native builds; isolate per-worktree output and key caches by exact toolchain/target/features/lock.
3. Discover cdylib/static output from compiler-artifact records and verify source/export/ABI hashes before staging.
4. Emit deterministic provenance manifest and fail stale/missing artifact or undeclared native dependency.

## 错误、取消、内存与并发

- Cancelled/failed build cannot package a previous success from an output directory.
- No Rust toolchain, network or Cargo build is injected into ordinary application/generator execution.

## 验收要求

- Cold/incremental/parallel worktree builds with intentional stale binding/failed compiler negative.
- Recorded commands/toolchain/target/source/lock/features and reproducible manifest; reproducibility differences investigated, never assumed bit-identical.

- Windows x64; Linux x64
- ordinary dotnet build/run; for generators/analyzers this describes the produced consumer, not the compiler host; explicit-RID Native AOT publish and actual consumer execution on the required OS rows
- Independent NuGet where this component is distributed; full no-Rust pristine consumer gates A16/B24.
- Exact source/lock/features/native/package/executable hashes; component tests cannot claim assembled product success.
- The task-specific cases below plus D04–D09; native and managed retirement separately observed.

依赖理由：start pins only actually consumed completed modules; acceptance adds local assembled-runtime checks where required. Reference links alone never become a global barrier.
