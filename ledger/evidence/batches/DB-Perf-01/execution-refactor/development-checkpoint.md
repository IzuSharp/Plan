# Development checkpoint before candidate freeze

This record separates implemented, tested development changes from the later clean candidate and its measurements. It does not grant any of the four required long cells. The three PRs remain open and the starting heads remain Korda `f0078da720e07031bc56464995af6791c41aaae8`, Design `335706d1d2c76f11d4e0eaffc4a35bf404776a19`, and Plan `bfe4aa3f074789dfac046412eff37fe6ba58b0f7`. Publication must recheck their current heads.

## Complete command and parameters

The selected command boundary retains one bounded, versioned representation of the dynamic Fluent graph. C++ consumes its original operand bytes once through the same semantic builders. It deletes the intermediate `command_clause`/`command_fields` decode, copied control frames, local-token rewrite and second schema parse. Text origin comparison borrows the original segments and only the first retained identity owns a copy.

A command-private `Impl::Edit` mutates the fresh, unpublished query arena in place. The former unconditional `QueryData` copy at every mutation/clause is gone on that route. Existing independent per-node ABI calls retain copy-on-success failure atomicity. Failed private edits poison and discard their unpublished arena and shadow parameter registry; private mode is reset before a root or clone escapes. Each sealed imported block still needs its immutable snapshot. The dead `QueryData.values` complete-frame storage and its uncalled `retained_counts` helper were deleted after a whole-checkout/caller search. Development validation passed 967 query assertions and 52 SQL/ordered-argument goldens, including late quota rollback and shadow-registry failure atomicity.

Prepared managed parameters now use one immutable header/descriptor/ordinal layout. Execution validates exact identities and copies current values into one independent frame under the parameter gate; sorting, snapshot-object arrays and cell arrays are removed. Native execution validates a borrowed frame, owns typed scalar values once, and sends those values directly to the provider. The second NWDB parameter encoding and provider reparse are removed. Raw expert SQL retains the original bytes only where frozen ABI exact-rebind equality actually consumes them. Legacy logical quota charges and SQL/parameter/shape error priority remain explicit rather than being silently relaxed.

## Provider, result arena and mapping

Fresh PostgreSQL Parse and Describe are queued in one libpq pipeline group before waiting, with a bounded terminal Sync/ReadyForQuery drain. No Bind or Execute occurs at cursor opening. SQLite prepares once for description and later binding of the same statement, without stepping it. Physical statement caching is not selected because fresh external-DDL semantics differ from cached fixed-result revalidation; no hidden retry/replay repairs that difference.

Both providers now preflight and convert the current row through one `RowSink`/`ScalarSink` path. The Host writes into a bounded `BatchWriter` allocation. Per-cell owned byte vectors, owning `Row`, pending decoded row staging, and the final `Batch::encode` copy are removed. A full batch can retain one provider row for the next fetch, but does not step that row twice. The arena begins with descriptor storage plus at most 1 KiB of payload reserve and grows within its admitted charge; it does not reserve the configured maximum for every small query. A final payload compaction and possible growth copies remain and must be reported.

Administration consumes the same provider conversion into its own flat payload/offset owner. It retains the previous per-field `MAX_BYTES` limit and its distinct aggregate-row behavior. Tests exercise nearly 4 MiB and 8 MiB ledger rows and preserve checksum error 15, dirty error 8, and mapped provider error 1 in the original order. The old owning scalar decoders and frame-to-provider parameter adapter have only test-private compatibility helpers now, without a second production path. An initial caller search missed `administration.cpp`'s dot-form `statement.next`; the deletion record explicitly corrects that mistake.

The managed batch already borrowed native memory before this work. The change does not claim removal of an earlier whole-batch managed copy. Validated layout proof is tied to exact projection identity and reused within the retained row lease; public reader lifetime, codec, ordinal, NULL and narrowing checks remain.

## EOF, admission and review corrections

The additive `db.result.batch.v1` extension leaves the frozen 42-function ABI and NWDB reserved fields unchanged. One result-take call transfers the owner and borrowed view, plus a definitive `known_end` observation. It never performs an extra provider read just to discover EOF. With a 32-row batch, actual 1/100/1,000-row queries used 1/4/32 fetch operations in both-provider development tests; exact 32/64-row boundaries still need 2/3 fetches because EOF has not yet been observed.

Independent review found that skipping the final empty fetch initially missed parent Session closure. A purely managed mirror also could not observe native-only source poison. The corrected route performs one synchronous native read-admission check at the consumed-known-EOF boundary. It shares the native cursor gate/state checks and observes source poison, but allocates no operation, fetches no row, sends no SQL or protocol message and incurs no deleted empty-fetch quota. Its one FFI call is a deliberate lifecycle-contract cost. Transaction/savepoint close waits for the cursor and must not introduce a new read refusal; disposing a captured query/plan does not invalidate its already-owned cursor.

The corrected development Host checks passed both providers' held-mapper Session-close/cancel/failure cases and pending/busy transaction controls, with all native owners drained. Fluent Native AOT passed 1,187 assertions across 28 cases and 428 managed retirements. These source-bound development results are superseded only by a later exact candidate run, not relabeled as one.

Independent review also found that the formal packer's exact export inventory had not yet included the result extension. The inventory now merges both reviewed extension schemas and checks their capability bits against the descriptor, keeping exact export equality. Formal independent package build/consumption remains required; earlier manually assembled test feeds do not satisfy it.

Natural PostgreSQL EOF is separately being adapted to reuse the same execution's already-observed ReadyForQuery rather than send another liveness-only Sync. This change is not accepted until actual proxy faults cover unfinished drain, a missing terminal reply, already-observed disconnect, later check-in/acquire detection, original SQLSTATE, Unknown and charged Host permit. COMMIT, recovery, pool and acquisition confirmations remain separate. No cost reduction is claimed at this checkpoint.

## Scheduling experiments and next measurement

Two isolated, unapplied experiments have passed component correctness checks: one separately queued retirement retry after a terminal callback races the final native lease release, and scanning only the occupied callback-slot range. The first is bounded to one prompt retry and still requires real native retirement before publishing its private result; a retained source returns to the existing timer. It passed 649 AOT async assertions with 107/107 native owners released. The occupied-range experiment passed 6,333 callback assertions with zero pending/active/root owners. These changes are not yet in the candidate and have no measured benefit claim.

The [before short observations](before-local/README.md) show the large current-host gap and later-batch latency. Freeze and measure the first integrated candidate before adopting a scheduling experiment. Reuse the existing local observer and public-package consumers, add the same-SQL Dapper phase reference, then calibrate fixed arrival rates. Do not run builds or another benchmark during a measurement window. Whole-process B/op is still not a proven framework/business split or a framework-wide 0 B result.
