## Finding1: complete managed DTO storage

The old fixed `4096*N` term admitted a600-byte request whose128 empty objects produced much wider serializer-created CLR bodies than the grant covered. An item with80 ordinary nested value properties allocated5,248,664 bytes; a single65,536-byte padded value property allocated8,394,392 bytes. The old complete grant was2,776,072 bytes, below both observed cases and the default4MiB request-side cap. Both calls reached the actual Handler and completed normally. These were plain source-generated DTO allocations, with no allocating user constructor or custom converter. The original `review.md` and frozen probe inputs preserve the counterexamples.

The repair derives a per-tool managed term from the exact static CLR storage closure. Public RuntimeHelpers.SizeOf gives the complete inline width of values, including ignored/private fields, nullable storage and explicit padding. Reference types use complete preserved declared fields, their bases, explicit offsets and StructLayout.Size, with conservative alignment/header allowances. Referenced objects are separate JSON nodes; private/ignored reference fields contribute their pointer slot without expanding an unrelated application heap graph. The node coefficient is `max(4096,4L)`, and the output term includes the maximum retained boxing path plus adjacent value-copy allowance. No reflection codec, runtime DTO instantiation or public API was added.

The finite compiler helper preserves closed source-known DTO/base fields using reachable DynamicDependency annotations. Inaccessible/private/generic definitions are exercised under NativeAOT. Its count proof includes backing fields, conservative event/primary-constructor slots, and the complete per-query reflection surface, including static/base/interface metadata that the actual runtimes may populate before instance filtering. Counts are checked before field arrays are requested. The final-compilation analyzer rejects a second generator's additional fields when they exceed the earlier proof.

External ProjectReferences use the SDK-supported implementation-assembly selector, so private-only implementation edits recompute the proof. A third-party reference-only compile asset cannot prove omitted fields and fails closed unless the actual static-context/DTO assembly supplies its own proof. This limitation is documented; it is not silently treated as complete metadata. Localized trimming suppressions are justified by the generated preservation contract and actual AOT witnesses, not described as reflection-free or suppression-free code.

**Closure:** the final actual Host fixtures cover both original width counterexamples, hidden/ignored/base fields, sparse explicit offsets, explicit class size, and output boxing. This is byte admission based on the implemented lookup path, not an arbitrary cap on unrelated direct DTO roots. The exact source derivation is in `assembly-lookup-review.md`; ten primary lookup files and nine previously inspected runtime reflection files are reproducible from the URLs/Git blobs/SHA256 values in the two source manifests.
